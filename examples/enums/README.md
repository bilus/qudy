# enums

This example writes two files for each enum: one with its `String` method, and
one with a `Parse` function. `main.go` is plain Go: it reads the arguments and
calls the two functions in `write.go`, which is the only template. Its first
line is `//go:build qudy`, so a normal build ignores it. `write_gen.go` is the
generator that qudy compiles from it, with `//go:build !qudy`.

One generator writes all the files. It prints a txtar archive, where a line such
as `-- unit_string.go --` starts a file. In the template that line is an
ordinary output line, at the top of the function that writes the file:

    func writeString(file, pkg, typ string, names []string) {
        //`-- ~{file}_string.go --
        //`// Code generated by the qudy enums example. DO NOT EDIT.
        //`
        //`package ~pkg
        ...
    }

`qudy -txtar` reads the archive from standard input, formats the Go files and
writes them under the directory that `-o` names:

    go run ./examples/enums -package units Unit=s,v,m Color=Red,Green,Blue |
        go run ./cmd/qudy -txtar -o ./units

The constants `s` and `v` have the plain names of the gensyms `s#` and `v#`, so
the generated code says `s_qd1` and `v_qd1`. `enums_test.go` runs that pipeline,
checks what each file holds, and tests the generated package.
